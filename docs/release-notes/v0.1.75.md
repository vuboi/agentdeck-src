### What's new

- **Stopped commands show as Closed.** A command in a terminal tab that is cut off, because its shell exited or its tab was closed, now shows "Closed" instead of finished, and sends a notification. A background task still running when AgentDeck closes shows "Closed" when AgentDeck opens again, with a notification.

### Fixes

- **`delegate_task` with a blank `continue` id returns an error.** Before, an empty id quietly started a new task instead of continuing the one you named.

### Developer notes

- Release version is `0.1.75`; the release workflow is triggered by the `v0.1.75` tag.
- Terminal run ends carry a `RunEnd` (`done` or `closed`) from `endRun` in `apps/desktop/src/lib/terminal/terminal-session.ts`; `trackTerminal` in `chat/runs/activity.svelte.ts` maps it to `ok` or `closed`.
- `closeRestoredTasks` (`apps/desktop/src/lib/chat/agent-reply.ts`) closes open background tasks when chats are restored at start-up (`chat/session/state.svelte.ts`). `TaskStatus` and `TaskRecord` gained `closed`.
- `sendSystemNotification` takes `{ evenFocused }` to send a notice while the window has focus.
- `account-rotation.test.mjs` stubs `./agent-status.svelte`, which `connectors.svelte.ts` imports.
- Known issues: reloading the window (F5) runs the same restore, so background tasks whose CLI is still running can show "Closed" until they report again. Dev servers started with `browser_serve` do not have a Closed state yet. A `stopped` chat task still shows "working" in the step line.
